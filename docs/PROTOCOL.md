# Протокол HeadlessHQ v1

> Расширение ручного протокола Штаба (база знаний, «Штаб и задачные сессии»).
> Один протокол — два режима запуска: вручную (человек) и автоматически (штаб-скрипт).

## Роли

- **Штаб** — основная сессия: нарезает работы, пишет файлы задач, запускает, принимает.
- **Исполнитель** — кодовая сессия (`opencode run --agent ispolnitel --dir <проект>`):
  читает свой файл задачи, делает, пишет отчёт, ставит статус. Диспетчер не трогает.

## Режимы запуска

| | Ручной | Авто |
|---|---|---|
| Кто запускает | человек фразой «`<Проект>. Читай docs/TASK.md`» | штаб скриптом `scripts/run-task.ps1` |
| Когда | неоднозначные работы, отладка протокола, отказ автоматизации | рутинные изолированные номера |
| Протокол | один и тот же | один и тот же |

## Жизненный цикл номера

```
открыта → в работе → на проверке → принята
```

1. Штаб пишет файл `docs/tasks/NNNN-слаг.md` (состав — как в ручном протоколе:
   цель, входит/не входит, старт, приёмка, ограничения) и строку о запуске
   в сменную часть диспетчера (время, номер, agent, модель).
2. Запуск: вручную или скриптом. Промпт-указатель один: «`<Проект>. Читай docs/TASK.md`».
3. Исполнитель первым делом ставит «в работе» — это proof of liveness: файл прочитан.
4. Исполнитель делает, проверяет по приёмке, дописывает отчёт (сделано, команды с выводами,
   тронутые данные, изменённые файлы, хвосты) и ставит «на проверке».
5. Штаб принимает: сверяет отчёт с приёмкой, переносит файл в архив, пишет в журнал,
   ставит галочку в плане. Файл правит только штаб после приёмки.

## Критерий успеха

Жёсткий: exit-код 0 **и** статус «на проверке» **и** отчёт с выводами команд.
Всё остальное — разбор, не приёмка. Повторный запуск того же номера дописывает
попытку в хвосты файла, номер не переиспользуется.

## Ограничения

- Параллельность — только между репозиториями (свой репо на сессию). Внутри одного
  репо номера идут строго последовательно: общие файлы, дев-серверы, живая база.
- Исполнитель коммитит и пушит только свой номер, чужие файлы не трогает.
- Слово штаба посреди номера объём не меняет: новая работа — новый номер или правка
  файла с новой приёмкой.
- Эскалация — через файл («стоп, спроси штаб» как статус), не через инструмент
  `question`: в headless отвечать некому.
